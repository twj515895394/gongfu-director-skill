# Gongfu Director Skill：上下文与交付流程优化实施方案

> 文档状态：设计方案，待分阶段实施与回归验证  
> 目标分支：`codex/context-routing-delivery-optimization`  
> 基线分支：`main`  
> 范围：优化 Skill 的上下文加载、能力路由、校验流程与交付产物；本次先落档，不直接重写现有规则库。

## 1. 目标与设计原则

### 1.1 核心目标

在尽量降低单次任务的上下文占用、重复阅读与冗长输出的同时，保持甚至提升打斗设计质量。优化不应以删掉专业规则、弱化用户要求或固定化创作方式为代价。

目标包括：

1. **按任务加载知识**：只读取当前任务所需的规则与示例，不因引用关系递归读取整套资料。
2. **按能力组合，而非单选分支**：动作体系、打击表现、剪辑方式、特效、质感、目标模型与校验强度相互独立，允许叠加。
3. **质量约束常驻，细节规则按需加载**：核心约束精简常驻；专项细则在需求明确或遇到问题时读取。
4. **校验执行与校验报告分离**：必要的质量检查仍须执行，但默认只输出关键结论；完整审计表按需展示。
5. **交付物按任务复杂度分级**：保留真正影响创作与生成的产物，减少重复表格、内部推理过程和不必要的文件。
6. **以回归测试证明无质量回退**：上下文节省只是指标之一，动作因果、空间连续性、风格命中与生成提示词完整性必须同时验收。

### 1.2 不可违反的设计原则

- **不把知识删减等同于上下文优化**：优先改变加载时机、模块边界和执行流程。
- **用户明确要求优先于默认配置**：例如用户要求“咏春近身短打 + 强重击感 + 克制特效”，不得因选中空手格斗就忽略重击，也不得因启用重击模块就把咏春改成大开大合的拳法。
- **动作技法与表现强度正交**：动作体系决定“怎么打”；表现强度决定“观众感受到多大冲击”。二者不得互斥。
- **核心质量底线不因精简交付而取消**：可以不展示所有审计过程，但不能静默跳过关键校验。
- **权威规则单点维护**：每条完整规则仍只有一个权威定义位置；摘要只做速查并链接到权威文件。
- **渐进式改造**：先修复路由与无条件读取，再拆文件、加脚本；避免一次性大重构引入质量回退。

## 2. 当前基线与主要问题

根据当前仓库内容的静态检查：

- `SKILL.md` 的仓库文件大小约 31.8 KB，文件内容约 15.5k 字符。
- `references/` 下有 30 份参考文件，文件原始大小合计约 397.7 KB。
- `action-timing.md`、`iron-rules.md`、`generation-feedback.md`、`look-quality.md` 等包含大量详细规则、案例或完整校验方法。
- 当前入口要求按需路由，但工作流仍要求在写稿前完整读取 `iron-rules.md` 与 `delivery-rules.md)，并要求大量校验项目；这些要求会扩大常见任务的实际读取范围。
- 空手格斗路由使用“空手（含重击流）”并同时列出空手经典路线与重击手册，容易被模型理解成两份都要读。
- `action-timing.md` 包含多类校验方法、示例和历史踩坑信息；普通任务不需要每次完整读取全部内容。
- 默认交付要求包含多份主体产物和大量审计表。审计过程、面向用户的结论与最终创作产物没有充分分层。

**数据口径说明：** 文件大小和字符数不是 Token 数，也不代表某次运行实际加载量。最终节省幅度必须通过目标 Agent/客户端的真实执行记录或 Token 统计测量，不能仅凭文件大小推算。

## 3. 目标架构

采用五层结构：

1. **入口层（轻量 SKILL.md）**：职责边界、意图识别、能力路由、核心质量底线、工作流与加载预算。
2. **常驻核心规则层**：简明且不可丢失的动作因果、空间连续性、时间约束、用户意图优先级、输出完整性规则。
3. **专业能力模块层**：动作体系、表现强度、剪辑方式、镜头语言、特效、质感、目标模型格式等。
4. **校验层**：确定性脚本校验 + 模型语义审查；专项检查按任务加载。
5. **交付层**：创作产物、用户可见摘要、内部审计记录分离；按任务复杂度选择交付档位。

建议将入口文件压缩到约 8–12 KB 作为初始目标，但不应为追求体积而机械删减。若关键规则摘要、路由或安全约束需要更多空间，以正确性优先。

## 4. 能力路由：正交维度与组合规则

### 4.1 任务配置（内部轻量 Manifest）

意图识别后，先形成一份简短任务配置；后续创作、校验与交付共用该配置，避免各阶段重新猜测用户意图。

建议字段：

- `action_style`：动作体系，如咏春/中线短打、重击技法、太极式化解、摔法、混合打法、元素对轰、魔法召唤。
- `impact_intensity`：打击表现强度，如常规、强化、极重击。
- `editing_style`：快剪、长镜头或混合。
- `vfx_profile`：无/克制/明显/高幻想；按具体需求进一步选择特效族。
- `visual_style`：写实、3DCG、动漫 CG 等。
- `target_model`：H3 或其他目标模型；未指定时使用通用输出。
- `deliverable_mode`：精简、标准、完整审计。
- `validation_profile`：基础、专项、完整审计。
- `user_constraints`：时长、镜数、画幅、人物、伤情、特写、禁用元素等硬要求。

该 Manifest 默认仅为内部执行状态，不需要在每次回复中完整展示。只有存在重要歧义时，才向用户确认。

### 4.2 动作体系与打击表现不得互斥

至少要覆盖以下组合：

| 动作体系 | 打击表现 | 预期效果 |
|---|---|---|
| 咏春 / 中线短打 | 强化 | 保留近身连续短拳与攻防转换，同时强化受力、命中反馈、镜头与音效 |
| 太极式化解 | 极重击反击 | 防守以偏转和借力为主，反击可有强烈冲击，不将整套打法改成连续重拳 |
| 大开大合拳法 | 克制写实 | 保留完整挥击与身体驱动，但不自动叠加夸张闪光或残影 |
| 空手混合技法 | 常规 | 按用户创意组合拳、腿、摔、闪避等，避免默认套用极重击规则 |
| 元素对轰 | 强冲击 | 用元素碰撞、光效、冲击波与声音塑造强度，不加载空手接触规则作为主模块 |

路由优先级：

1. 用户明确指定的风格、招式倾向、强度与限制。
2. 常驻核心质量底线。
3. 当前任务所需的专业模块。
4. 未被用户指定时的默认偏好。

当用户的明确要求存在真实冲突时，指出冲突并给出选项；不得擅自用模块默认值覆盖用户意图。

### 4.3 分层加载策略

- **常驻核心**：入口中的精简铁律、任务配置、用户意图优先级、最小质量门槛。
- **按任务必读**：已选动作体系、已选剪辑方式、所需输出格式与对应核心模板。
- **按特征加载**：重击强化、复杂物理交互、特殊特效、特定质感、长镜头细则等。
- **问题驱动加载**：生成失败案例库、研究参考库、历史问题诊断资料，仅在相似问题出现或用户要求分析时加载。
- **不相关模块禁止加载**：不因一个模块引用了其他文件，就自动递归读取所有被引用文件。只有当前任务实际使用该能力时，才打开其权威规则。

### 4.4 重击能力的三级加载

1. **常驻基础命中规则**：每次命中都要交代接触对象、受力方向、身体反应与动作结果。保持精简并纳入核心规则。
2. **轻量打击强化模块**：用户提到“拳拳到肉、打击感强、冲击明显”等时启用；涵盖身体受力、命中反馈、镜头微震、音效及适量环境响应。
3. **完整重击专项模块**：用户要求极重击、高速冲刺重击、大幅轰退、动漫冲击帧/残影配额，或轻量方案不足以实现效果时，才读取 `heavy-impact-playbook.md` 中相关章节。

若当前工具无法按章节读取，第一阶段可先建立精简版强化文件，再将完整手册作为专项深读材料；不得为了实现“章节加载”而假设工具具有实际不支持的能力。

## 6. 工作流调整

### 阶段 0：解析意图与约束

- 从用户自然语言提取动作体系、表现强度、剪辑方式、特效、质感、目标模型与交付需求。
- 只对影响路线选择的关键歧义提问；其他未提供参数沿用合理默认值。
- 用户要求明确时，不因默认规则而重复追问。

### 阶段 1：生成轻量任务配置

- 形成内部 Manifest。
- 列出本次将读取的模块与原因。
- 设置任务复杂度和校验档位。
- 不在用户未要求时输出冗长的模块清单。

### 阶段 2：按路由读取规则

- 加载核心规则摘要和当前任务所需模块。
- 仅在具体任务命中时读取完整权威规则、案例库或长篇示例。
- 发现规则冲突时回查权威文件，不能靠摘要猜测。

### 阶段 3：创作

- 按用户确认的动作体系与表现强度生成内容。
- 同时考虑动作因果、角色关系、空间与镜头、受力反馈、风格限制。
- 不能为节省上下文而省略用户明确要求的招式、镜头、数值或效果。

### 阶段 4：分级校验

- 先运行基础确定性校验。
- 再运行任务专项校验。
- 对语义问题做模型审查。
- 只有失败项、冲突项或风险项才触发深度诊断与额外资料加载。
- 必须保留用户要求的关键质量底线；精简模式只精简报告，不等于取消检查。

### 阶段 5：交付与迭代

- 交付最终产物和关键结论。
- 默认不把所有内部检查表、重复计数过程和长篇规则解释塞入聊天回复。
- 修改版本时，先给变更摘要；如用户需要可继续查看差异。凡用户要求完整新版文件时，仍提供完整可用产物，不用局部补丁代替成品。
- 对生成失败做复盘时，按具体问题加载 `generation-feedback.md` 与相关规则。

## 7. 交付产物精简方案

### 7.1 交付模式

| 模式 | 适用情况 | 主要交付 |
|---|---|---|
| 精简模式 | 创意探索、快速试稿、局部修改 | 核心分镜/修改结果 + 可执行提示词 + 关键风险提示 |
| 标准模式（建议默认） | 一般正式创作 | 中文分镜审阅稿 + 生成模型可直接使用的完整提示词 + 必要的调度信息 + 关键校验结论 |
| 完整审计模式 | 最终定稿、复杂群战/长镜头、用户要求严格验收 | 标准交付 + 详细密度/动作链/伤情/连续性/版本差异等审计报告 |

### 7.2 产物分级

**A. 核心创作产物**

- 中文分镜表：便于用户审阅与修改。
- 生成模型可直接使用的完整提示词：按目标模型选择中英双版或 H3 纯英文六段式等正确格式。
- 必要的空间调度信息：用文字或图示表达人物位置、方向与运动关系，具体形式根据复杂度选择。

核心产物必须自洽、完整、可执行。不能为了缩短回复而把必要的动作描述、镜头字段、音效、用户指定数字或模型格式要求删掉。

**B. 条件式辅助产物**

- 俯视调度图 PNG：多人空间关系、复杂位移、长镜头、轴线风险较高或用户要求图示时，作为强交付；简单场景可先用精简调度说明。是否将其设为所有任务的必交产物，须经回归测试后再决定，避免未经验证直接删除现有承诺。
- 参考研究摘要：只在确实执行研究且研究结果影响创作时简短说明。
- 版本差异表：仅在重设计或用户要求比较版本时输出。
- 专项图表：只在对应专项存在时输出。

**C. 内部校验记录 / 可选审计产物**

以下内容默认在内部执行或记录，标准模式只汇报结论与异常：

- 每秒拍点、时长、字符数等详细计算过程。
- 完整禁词扫描命中清单。
- 每镜景别、运镜、机位、动作分布的全量统计表。
- 完整伤情表、连续性接点表、重设计相似度表。
- 所有检查项的逐条“通过”清单。

这些内容不能一概取消：当它们揭示风险、用户明确要求审计，或特定任务规范要求完整报告时，必须按完整审计模式输出。

### 7.3 默认回复的推荐结构

1. 交付内容与文件清单。
2. 逐镜速览（根据镜数与任务复杂度控制篇幅）。
3. 校验结论：通过项摘要、失败项、需要用户决策的风险。
4. 必要的时长对账与生成风险提示。
5. 仅在适用时提供版本差异或专项审计。

避免在正文、摘要和审计表中重复展示同一份提示词。提示词文件作为权威完整产物，聊天正文可以显示速览和关键片段；如果用户要求直接在对话中查看全文，则完整输出。

### 7.4 迭代时的产物策略

- **局部修改**：先展示改动摘要和受影响镜号；按需提供完整文件或更新版文件。
- **完整重做**：生成完整新版产物，并执行重设计差异检查（若有旧版可比）。
- **探索稿**：不默认生成全部辅助图表；用户确认方向后再进入标准/完整交付。
- **最终定稿**：按用户要求与任务风险升级为标准或完整审计模式。

不得让“精简交付”成为隐性删减用户创作内容的理由。

## 8. 自动化校验工具建议

建议新增 `scripts/validate_storyboard.py`，但需先验证现有分镜格式，避免脚本依赖脆弱的正则或误判正文。

### 8.1 适合确定性脚本的检查

- 时间码格式、递增关系、镜号完整性、总时长计算。
- 目标模型提示词字符数/长度限制（明确统计口径）。
- 必需字段和输出文件是否齐全。
- 参考图编号、镜号与调度图镜号的一致性。
- 已有明确定义的禁词/结构扫描。
- 可机器解析的拍点计数与节拍窗口统计。

### 8.2 应由模型/人工审查的检查

- 动作链是否具备起手、接触、结果。
- 受力方向、人体姿态与运动轨迹是否成立。
- 角色相对位置、银幕方向、轴线和切点是否连贯。
- 招式是否重复、攻防是否失衡、动作体系是否符合用户意图。
- 重击表现是否与整体风格相符，是否过度叠加静帧、残影、闪光、震动。
- 镜头设计是否真正服务于动作，而非堆砌术语。

脚本应输出结构化结果（例如 JSON），明确区分 `error`、`warning`、`info`。不能将词表命中直接当成语义错误；脚本报告异常时，应允许模型复核并标记误报。

## 9. 上下文预算与测量

### 9.1 测量原则

不能把文件字节、字符数或“加载了几个文件”直接等同于 Token。应优先使用目标执行环境提供的 Token 统计或上下文使用量；若不可用，再以实际读取内容字符数作为代理指标，并明确标注为估算。

建议每个测试任务记录：

- 任务类别与复杂度。
- 实际读取的文件列表、读取范围与原因。
- 可获得的输入 Token、输出 Token、峰值上下文使用量。
- 是否触发专项模块、失败诊断与完整审计。
- 用户可见输出长度与产物数量。
- 质量回归结果与人工评审意见。

### 9.2 初始优化目标（待实测校准）

- 常见普通打斗任务的中位输入 Token 相比基线下降至少 40%。
- 混合任务（如咏春 + 强重击 + H3）只加载必要的动作与表现模块，不因维度组合而加载整套知识库。
- 不出现“用户明确要求但因未加载模块而漏掉”的情况。
- 默认回复减少重复审计文本，但核心交付产物仍完整可用。

以上为建议的初始验收目标，不是当前已测得的结果。若实际 Token 统计不支持精确测量，应先建立可重复的基线再设定硬阈值。

## 10. 回归测试矩阵

每轮实施都应运行以下代表性用例，并保留优化前后的产物供对比：

1. 普通空手近身格斗。
2. **咏春短打 + 强重击感 + 克制特效**（防止动作体系与打击强度互斥）。
3. 大开大合重击流 + 明显冲击反馈。
4. 太极式化解 + 极重击反击。
5. 元素对轰 + 强冲击视觉效果。
6. 魔法召唤 / 大规模技能效果。
7. H3 六段式提示词与字符限制。
8. 长镜头一镜到底。
9. 3DCG 质感与特效约束。
10. 复杂多人调度、方向连续性与俯视图。
11. 重新设计版本：差异化约束与原意保留。
12. 生成失败诊断：只加载相关案例和专项规则。

### 10.1 质量评分维度

每项按 1–5 分评分，必要时附具体缺陷：

- 用户意图命中。
- 动作体系准确性。
- 打击表现与风格一致性。
- 动作因果与身体受力。
- 镜头与空间连续性。
- 时间码与时长约束。
- 目标模型格式合规。
- 交付完整性与可直接使用程度。

建议将“用户明确要求未满足”“核心动作链断裂”“严重空间跳变”“目标模型格式错误”设为硬失败，不允许被总分平均掩盖。

### 10.2 上线门槛

- 核心质量维度不得出现系统性下降。
- 所有硬失败用例必须通过。
- 上下文指标有明确改善。
- 不相关模块的读取次数明显减少。
- 默认交付不再重复大段审计内容，且用户仍能获得必要产物。
- 任何条件式产物的默认省略，都必须通过相应场景回归测试。

## 11. 分阶段实施路线

### Phase 1：路由纠偏与强制加载清理（优先级 P0）

- 修正空手与重击路由，明确动作体系和表现强度是独立维度。
- 删除工作流中的无条件全量读取要求，改为核心摘要 + 条件深读。
- 为创意库、历史案例库、质感库和专项校验补上明确触发条件。
- 暂不删除任何权威规则，不改变已承诺的关键交付内容。
- 增加“咏春 + 强重击 + 克制特效”回归用例。

### Phase 2：入口精简与模块边界调整（优先级 P1）

- 将 `SKILL.md` 精简为入口、路由、Manifest、工作流和核心摘要。
- 将 `action-timing.md` 按校验领域拆分，或先建立可按范围读取的校验目录与索引。
- 将 `camera-language.md` 的核心空间规则与技法目录分层。
- 为重击强化建立精简模块，完整手册保留为专项深读。
- 检查权威定义和跨文件引用，避免规则重复、悬空链接与循环加载。

### Phase 3：交付模式与产物分级（优先级 P1）

- 明确精简、标准、完整审计三种交付模式。
- 默认只展示关键审计结论；完整表格按需输出。
- 根据任务复杂度评估调度图、专项统计表和版本差异表是否必交。
- 保留用户要求的完整最终提示词与正式交付文件。
- 先通过回归测试，再调整任何现有默认交付承诺。

### Phase 4：校验脚本与运行指标（优先级 P2）

- 开发并测试 `validate_storyboard.py`。
- 将确定性检查从模型上下文中移至脚本。
- 建立上下文/Token、模块加载、输出长度与质量评分的对比记录。
- 对常见任务建立固定回归样本，后续修改规则时持续复测。

## 12. 实施边界与风险控制

- 本方案落档不代表上述代码或规则已修改。
- 不一次性重写全部 references；每个阶段都要可独立审查与回滚。
- 不因上下文预算不足而默默省略用户指定的镜头、动作、数值或特效。
- 不把所有“重击”统一解释成大开大合；表现强度和动作体系始终分离。
- 不把“校验报告精简”误解成“减少必要校验”。
- 不在未经回归测试前取消俯视调度图等现有交付承诺。
- 不把引用文件的所有内容自动递归加入上下文；需要时读取权威定义，避免引用链膨胀。
- 如果运行环境不支持真实 Token 统计或精确章节读取，应记录限制并采用可验证的替代方法，不伪称已实现。

- [ ] “咏春 + 强重击 + 克制特效”测试证明不会丢失任何指定特征。

- [ ] 所有权威规则仍有唯一来源，引用有效，没有明显的循环加载与悬空文件。
