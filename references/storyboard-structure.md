# 分镜结构 · 写法模板

> 标准交付：中文分镜表 `.md`（给用户审阅）+ 与目标模型匹配的完整提示词（默认必出；H3 时为本文件定义的纯英文六段式 `.txt`，全选即粘、零中文），两者逐镜对齐。俯视调度图 PNG 按 `output-format.md` 的复杂度/用户要求条件交付；不出 PNG 时仍必须写清轴线与逐镜空间关系。标准模式的审阅摘要 = 中文分镜表 + 对话回复里的精简逐镜速览。
> 不写【输出检查】段落（自检数字写在对话回复里），十项字段名不印在稿里，只作内部写作清单。

禁止用 markdown 表格承载镜头内容（稿内逐镜用自然语言段落）。

## 一、detailed_description 内部的段落顺序（固定）

```
风格总纲 —— 整体是什么片子（渲染管线 / 质感 / 色调光影），写成句子，不堆标签
持续元素段 —— 全片贯穿的物理元素（风 / 雨），一次声明 + release clause（「除某镜另行说明，这层运动一直在画面里跑，不必逐镜重申」）
结构约束块 —— 镜数与时长链 · 硬切禁令 · 防融合 · 轴线与左右关系 · 状态等式句 · 参考图优先 · 禁漫画效果线
逐镜段落 × N —— 每个镜头一个独立段落块，切点字面写 `[Shot N] At MM:SS.mmm, CUT TO:`
```

音乐一律不写：`non_diegetic_music: N/A`（必须显式写 N/A，不能留空）。前三段的先后可以微调，读起来顺即可。

## 二、风格总纲的写法

必须覆盖五项，每项一到三句，用自然语言叙述：

1. 风格总纲 —— 整体是什么片子（如「UE5 次世代 AAA 仙侠 CG，低对比」）。渲染管线细节（PBR / Lumen / Nanite / 光追 / 皮下散射 / 逐缕解算）可并列，但写成句子。
2. 画面质感 —— 皮肤什么质感、头发怎么解算、颗粒 / 雾 / 景深什么状态、整体收尾风格。
3. 色调光影 —— 主色调、对比度、高光性质（柔光 / 硬光）、边缘光、低饱和还是浓郁。
4. 场景锚 —— 哪张参考图定义环境；密度 / 雾 / 色温 / 空间构图是否全片一致。
5. 全片贯穿元素 —— 持续存在的物理元素（如「全片始终有强风」），并说明它带动了哪些次级动作（头发翻飞、衣物抽打、落叶翻滚、竹叶飘过）。

> 若用户给了全片统一的人物朝向，必须写进这一节，用一句祈使句钉死。
> 例：`the fighter faces screen right for the entire film — the camera always watches him from his right side`。

## 三、subject_definitions 的写法

> 不读图也照写：只写「哪张图是什么用途 + 什么时候用它的哪一部分」，一个字都不写图里的内容。

逐张列出，每张一段：

```
<Subject 1> is character A, defined entirely by <Picture 1> (four views left to right:
facial close-up / front full body / left side full body / back full body). Every
facial appearance takes the leftmost facial close-up cell; body, clothing, hair and
hands take the three full-body cells by camera angle.
<Subject 2> is character B, defined by <Picture 2>, same four-view layout and locking rules.
<Subject 3> is the environment, defined entirely by <Picture 3>.
```

必须显式写出：

- 脸部只取图 N 最左侧那格的面部特写；身体和衣服取中间三张全身图（取用细节见 `iron-rules.md` 铁律 7）。
- 哪张图用来定义什么（角色 / 场景 / 道具 / 构图 / 材质）。
- 参考图优先于文字：写出「凡文字描述与图 N 冲突，以图 N 为准」。
- 一张图若还承担构图职责，单独说明它锁死了哪些构图要素（主体在画面什么位置、占多大、画面底部是什么、背景是什么、机位高低）。
- 同一主体出现在多张图里时，说明以哪张为主、其余作补充。
- 不要描述角色的长相、发型、服装、身材——只说「以图 N 为准」。

## 四、逐镜段落

内部按十项写，输出时不铺字段名——用自然语言把信息揉进一到两段话。

内部检查清单（写完逐项对一遍，缺哪项补哪项）：

```
[Shot N] At MM:SS.mmm, CUT TO:      ← 切点字面，字面
----------------------------------------------------------------
景别构图：  镜别 + 机位在哪 + 主体在画面什么位置 + 朝向 + 前景 / 背景
主体：      谁在画面里，各占什么角色
参考图：    这一镜实际用到哪张图的哪个部分（脸部点名调用最左格）
镜头运镜：  静态还是运动；方向 + 幅度 + 速度；**必须在本镜内完成**
动作：      按发生顺序排列；动作数量要能装进该镜时长
服装头发：  风中 / 运动中的状态
环境光：    本镜的光照与色调；与全片一致时不必重复
音效：      不写在这里——归 overall_soundscape
转场：      硬切 + 驱动这次切换的匹配逻辑
```

### 措辞要求（英文稿里写清、速览表里大白话）

| 不要只写 | 要写清 |
|---|---|
| `low-angle medium shot` | 机位在主体下方、从下往上仰拍，框到全身与脚下地面 |
| `over-the-shoulder` | 从谁的肩后看过去，前景是谁的肩 |
| `POV switch` | 镜头从甲的侧面一下换到他的正下方（镜内跳换，不是切） |
| `holds for a single frame` | 停了 0.150 秒，正好停在被勾住的那一瞬 |
| `camera follows the cloth` | 镜头是跟着布走的，不是留在它被割断的地方 |
| `handheld` | 手持、画面轻微在晃，晃动有来由（跟着出拳 / 跟着受击 / 跟着落地） |
| `tight frame` | 镜头贴得很近，只看到他半身 / 只拍到手上的动作 |
| `locked-off` | 这一镜镜头是架住的，一点都不动 |

时间码：精确触发点必须给到毫秒，不许写「约」。

打斗类附加（逐镜检查）：

- 速度标注 —— 这一镜是极快、正常，还是有关节节点的慢动作；含 ramp 时显式写变速曲线（起点 / 降速倍率 / 保持时长 / 回到 1.0x 的时刻）。
- 手持与景别 —— 逐镜写明手持还是固定，手持要写出晃动的来由；逐镜写明景别，重拍组那几镜给中景（铁律 6）。
- 反应时序 —— 预动写进挥满格的「已经…」里（`— and <Subject 2>'s knees are already bending`），确认起躲在前。

> 三条铁律见 `iron-rules.md` 铁律 2 / 6 / 5。

## 五、overall_soundscape 的写法

分三层叙述，每层一到数句：

1. 环境底噪 —— 全片持续存在的环境声（风、水、林、room tone）。
2. 物理动作声 —— 由主体动作触发的声音事件，标注对应的镜头或时间点。
3. 主体声的远近处理 —— 主体在画面里很远很小时，它的衣物 / 呼吸 / 脚步要单独写「遥远、微弱」，与满量级的声源形成距离差，否则声画空间感会打架。
4. 人声逐人定义（必做） —— 每个角色的音色在音效层开头单独写清（性别 / 音区 / 发力声形态），全片每个发声事件带 `(Sx)` 声源标签，禁令写全（如 `no male voice, no deep voice, no growl anywhere`）；开场尽早安排一声锚定音色。只写一句总闸压不过模型默认值——实测见 `generation-feedback.md` 案例 3。

禁止断言与画面矛盾的材质：某物体的材质是渐变或混合时（如上段深黑、尖端亮银），音效里不要写具体材质，只描述动作与质感，把材质留给设定部分精确表达。

> 跨镜汇总最容易出幻觉——每个次数与镜号逐个对回正文（见硬规则 9）。

## 六、篇幅与详略

- 信息密度高的镜头（多 beat + 材质 + 光照 + 运镜）允许长，不许为压篇幅砍他的细节；但不注水，每句都要带可执行信息。
- 镜头极多时（如 20 镜蒙太奇）逐镜收紧为短句，重复的设定（环境光、服装状态）合并引用。
- 字符上限 7,000（H3 单文本项，按字符数计）——先分清字符还是 token 再压缩。
