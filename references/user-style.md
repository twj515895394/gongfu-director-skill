## 一、核心立场：优化 ≠ 大面积修改

用户说「优化」「润色」「调整」时，默认保留原意与小细节：

- 保留：大纲的原句、镜头顺序、关键动作、动作的具体数值、他自己起的称呼、他写的材质 / 颜色 / 光照描述。
- 只补：官方要求的字段结构、缺失的语义（如「这个动作持续多久」「这一镜谁在画面里」）、格式规范（时间码精度、标签一致性）。
- 不要：换一套自己的表达、重写他的画面想象、删减他刻意设计的细节。
- 只有他明确说「重写」「推翻重做」「完全换一种思路」时，才允许动骨架。

> 判断标准：产出应该是「他自己那份东西变整齐了」，而不是「别人重新写了一份」。

## 二、精炼优先

砍修辞，不砍信息。

| 砍掉 | 保留 |
|---|---|
| 虚词：「的」「了」「就」「在…上」「进行」「属于」 | 动作顺序（1) 2) 3)） |
| 冗余修饰：程度不重要时的「微微」「稍稍」 | 所有数值与时间码 |
| 同义重复 | 朝向、参考图引用 |
| 自我总结（前文已写「同 Shot 1」又复述一遍设定） | 材质、颜色、光影的具体描写 |

典型压缩：
`把角色1的衣摆与拖尾飘带甩向与运动方向相反的一侧（起点惯性的反向摆动），布料先达到一个小幅延展、再回落稳定`
→ `把角色1的衣摆与飘带甩向运动反侧（起点惯性反向摆动），布料先小幅延展、再回落稳定`

不要为了短而删动作。 他宁可长一点，也不接受漏掉一个 beat。

## 三、高频用词与表达习惯（沿用）

### 结构类词

| 用户习惯 | 用法 |
|---|---|
| 景别 / 构图 合并为一个字段 | 不要拆成两个 |
| 镜头 / 运镜 合并 | 常写「（quick horizontal tracking right）」这类中英对照 |
| 服装 / 头发 合并 | 不拆开 |
| 场景锚 | 「哪个参考图定义环境」 |
| 转场匹配 | 不叫「转场方式」，要写出驱动的匹配逻辑 |
| 硬切 | 唯一允许的转场；强调「无 dissolve / 无 fade / 无转场特效」 |
| 全片始终有… | 描述贯穿元素 |
| 次级动作 | 被主元素带动的次要运动（风 → 头发 / 衣物 / 落叶） |
| 起势 / 蓄势 / 承诺交锋 | 他描述武打节奏用的词 |
| motif 复现 | 他会刻意让某个动作在片中复现几次 |
| 关节节点 | 关键节点，也是慢动作的唯一合法位置 |
| 极快 | 描述打斗速度的默认要求——不是形容词，是硬指标 |
| 手持 | 默认拍摄方式；景别随动作幅度放开（铁律 6） |
| 及时的反应 / 预判 | 守方动作先于攻方命中 |
| 四视图 / 最左侧 | 脸只取最左那格的面部特写 |
| 一个来回 / 拍 | 密度单位：一个来回 = 甲攻乙应对 = 2 拍 |
| 僵持 / 压制 / 被压制 / 退了要顶回来 | 位移只由压制关系触发；谁被压由他点名，他没说就只加一点点 |
| 交接给下一镜 | 分镜里取代「镜头结束时」的字段名 |
| 见血 / 还回来 / 到不到下 | 伤情相关：中了就见血、伤要还回去、谁倒由他定 |
| 侧身闪避 / 翻滚 / 后空翻 / 后下腰 / 扫堂腿 | 他点名的化解动作——不许只会架挡，各大类换着用（铁律 10） |
| 下腰 / 铁板桥 | 腰向后折、脚钉地、对方攻击贴面过——他说的「后下腰」就是这一招 |
| 解法不重复 / 动作太单一 | 他的验收口径：连续两镜化解不许同类 |

### 描述动作的方式

- 编号列表：`1) … 2) … 3) …`，每条一个动作或一个状态，不写成长段。
- 用「·」连接同一条里的并列要素：`右手出拳·拳面朝下`
- 关键约束加粗：`必须在本镜内完成，不跨切`
- 强调「几乎不动」时说明能量来源：他常写「两人几乎不动，视觉能量全部来自风带动的头发、衣物、落叶」
- 写距离关系：`两人之间保持明显空间距离，不贴身`——他很在意空间是否合理。

### 节奏 / 视角高频词（其余见 `action-sourcebook.md`）

| 用户/流派习惯 | 用法 | 出处 |
|---|---|---|
| 急停 / 顿进 | 动 → 静止 1-3 帧 → 再动（动漫合法语言，不是慢动作） | 思路 4 |
| 连击因果链 | 前一个动作是后一个动作的因，每招都有目的 | 思路 1 |
| 环境交互 / 道具即武器 | 树干、竹枝、衣服、碎石——能抓的全是兵器 | 思路 8 |
| 连消带打 / 中线 / 黏手 | 中线短打、双手收中线、攻防同一拍 | 咏春（叶问路线） |
| 借力 / 补击 / 截击 / 躲击 | 攻防转换五类（化解+借力+补击+截击+躲击） | 思路 1 衍生 |

### 精确性习惯

- 时间码精确到毫秒：`00:02.000`、`00:05.800`，从不写「约」。
- 时长写三位小数：`3.000s`、`0.500s`
- 动作要能装进时长：他会主动问「这个时间够不够完成」——产出应主动附校验。

## 四、参考图：怎么引（默认不读图）

> 默认不读图：图 1 / 图 2 / 图 3 由用户自己直接交给 H3。
> 产出方不去读、不去目录里找图、不把图里的内容转写成文字——只在稿里按编号点名（`the face takes the leftmost cell of <Picture 1>`、
> `the environment follows <Picture 3>`）。下面的放大读图法仅在他当轮明确问形状 / 材质时启用。

图片优先于文字：哪怕冲突的文字来自他自己的大纲，也以图为准。

1. 读图必须放大分区看——整图缩略会误判形状与材质。用 PIL 按 上/中/下 × 左/中/右 裁 4–6 块，各自放大到 900–1000px 宽再读。重点复查：几何形状（直 / 弯）· 脊线结构 · 表面质感 · 颜色是否渐变 · 数量密度 · 视角 · 景深 · 前景遮挡。
2. 检查联动矛盾：材质、颜色、密度一变，音效、光照、景深描写全部要复核——最常见的疏漏是音效引用了已被修正的视觉特征。
3. 他问「这是弯刀吗」这类形状确认时，必须实际裁切放大后回答，不能凭缩略图判断。
4. 图号由他指定 · 不主动翻目录找图 · 四视图取用规则见 `delivery-rules.md` 硬规则 3 与 `iron-rules.md` 铁律 7。

## 五、工作流与交付习惯

流程本体见 `SKILL.md` 的工作流五步，交付形态全文见 `delivery-rules.md` 硬规则 1，本节只记他的个人习惯：

- 不要在第一步就产出结构化分镜：他要先看懂、先纠正理解偏差。
- 自检结论写在回复里，不落盘。
- 与他的原意有偏差，立刻说明改了什么、为什么，不静默修改；风险主动提示并给取舍建议，由他决定。
- 人读输出是对话回复里的逐镜速览表（中文、大白话）：一句话一镜，术语解释清楚。
